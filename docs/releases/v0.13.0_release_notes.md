# Release Notes - v0.13.0 (2026-06-01)

## 🚀 Performance Audit & High-Performance Optimizations (Phase 18)

This release ships a comprehensive performance audit and major speedups across the well log rendering and data loading pipelines, resolving regression UI lags and optimizing cold-start times.

### ⚡ Rendering Optimizations
- **WellLogCanvas Static Frame Caching (QPixmap)**: Introduced an intelligent caching layer in `WellLogCanvas` that renders static track elements to a `QPixmap`. Crosshairs and dynamic overlays are now painted directly over the cached image, slashing mouse hover latency from ~50ms to **<0.5ms** and enabling buttery smooth 60+ FPS performance even with 10+ wells visible.
- **CurveTrack Path Caching & Vectorization**: Replaced redundant scalar Python `lineTo()` loops with matrix-based NumPy coordinate mappings. Mapped `QPainterPath` instances are now cached based on viewport geometry and depth range, enabling near-instantaneous redraws (<1μs on cache hits) and eliminating CPU bottlenecks when scrolling or resizing.

### 📦 Data I/O & Loading Optimizations
- **Lazy Excel Sheet Loading**: Transitioned from parsing all Excel sheets upfront to an on-demand `LazySheetDict` implementation (`src/data/loaders.py`). By only parsing sheets (like '测井曲线' or '地层系统') when explicitly requested by keywords, cold-start initialization latency is reduced by 30-50%.
- **Binary Format Cache (Pickle)**: Overhauled the internal caching engine to utilize high-performance Python `Pickle` binaries instead of serialized JSON strings. This bypasses costly `float('nan')` text conversion and skips Pydantic schema validation on cache hits, yielding **3x-5x faster** disk read performance.
- **Parallel Multi-Well Loading**: Implemented concurrent threaded data loading via `concurrent.futures.ThreadPoolExecutor` in `CrossWellPage`, allowing multiple well datasets to be queried and parsed in parallel while meticulously preserving the user's selected ordering.

### 🛠 UI/UX Improvements & Bug Fixes
- **Cross-Well Correlation Bug Fixes**:
  - Restored the missing **"手动连井" (Manual Linking)** button in the multi-well correlation UI.
  - Resolved an event-interception bug using Qt event filters, allowing child canvases to properly forward mouse clicks for picking/correlating formations across wells.
  - Fixed a critical alignment offset where correlation bands were displaced upwards by 28px due to an incorrect `mapTo` hierarchy calculation in `ConnectionOverlay.depth_to_y()`.
  - Added reactive signal connections (`depth_range_changed` → `update`) to ensure all correlation overlays precisely track and rerender in sync with zoom and pan operations.
